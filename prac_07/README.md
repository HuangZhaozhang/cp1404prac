## Clean Code Lessons Learned

Through the CP1404 subject, I have learned several important lessons about writing clean and maintainable code:

- **Meaningful Naming**: 
- Using descriptive and intention-revealing names for variables, functions, and classes makes code more readable and self-documenting
- **Single Responsibility Principle**: 
- Each function or class should have only one reason to change, making code more modular and easier to test and maintain
- **Consistent Formatting**: 
- Maintaining consistent code style and using tools like "Reformat Code" improves readability and collaboration
- **DRY Principle**: 
- Avoiding code duplication by extracting common functionality into reusable functions or methods
- **Clear Documentation**: 
- Writing helpful comments and documentation that explain why certain decisions were made, not just what the code does
